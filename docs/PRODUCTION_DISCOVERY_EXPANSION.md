## Contracts and extension points

- `directory-adapters.ts`: `DirectoryAdapter` returns deduplicated links, bounded next-page links and exclusion counts. `official-html-1` retains reviewed selectors. `official-jsonld-list-1` reads ItemLists and applies the same URL and candidate policies. It does not follow metadata URLs automatically. HTML pagination remains limited to three pages/two outgoing page links and 100 candidates per check.
- `adapter-registry.ts`: `OpportunityAdapter` has an identifier, supported media, URL classifier and extraction contract. Existing Makerere/Twente extractors are registered unchanged. Adding an adapter requires one registry entry and reviewed source policy, without editing the core worker. Unknown adapter identifiers cannot be enabled.
- `reviewed-html.ts`: reusable templates require one reviewed content root, scholarship heading, institution evidence, funded-level evidence and provider section headings. Admission qualifications do not become funded levels. Funding prose, requirements, procedure, country restrictions and other source wording are retained without converting them to unsupported rules. Original passages are checked by the existing validator.
- `structured-metadata.ts`: reads bounded JSON-LD graphs, Grant/MonetaryGrant/EducationalOccupationalProgram fields and ItemLists. No remote context or reference fetches. Malformed data and conflicting opportunity URLs/names require review. Dates remain raw metadata until separately validated; metadata is never an automatic source approval.
- `pdf.ts`/`pdf-parser.mjs`: PDF.js text extraction runs in a separate worker with a 10-second timeout, 128 MiB JS heap limit, 2 MB download, 30-page limit and 80,000-character text limit. Only PDF MIME/signature is accepted for an explicitly configured PDF policy. Scans without text, encrypted/unparseable files and unsupported layouts require review. No embedded actions are executed or attachment links followed. The registered PDF adapter requires a reviewed exact mapping; no live PDF provider was approved in this increment.

URLs are checked for encoded separators/dot traversal before URL normalisation. Canonical identity must match the exact reviewed page, including same-host changes. A source-URL lock and accepted-version lookup prevent a conflicting new programme identity from publishing the same URL twice. Stable programme keys and explicit academic-cycle statements separate new cycles; dates alone never establish intake identity.

The publisher remains conservative: no date/timezone/GPA guesses, no comprehensive funding inference, no complete-eligibility claims, and no removal of accepted facts after retrieval or layout failure. Unmapped mandatory conditions retain provider confirmation. Changed source facts and funding/conditions remain reviewable material changes. Repeated observations retain history without adding versions/events when content is unchanged.

## Safe operator onboarding

1. Inspect policy metadata with `npm run sources:discover -- --list` (read-only), or the operator's “Reviewed sources and supported adapters” panel.
2. Review the official identity, routes, current robots/access policy, selectors, identity/cycle grammar and fixtures. A source being listed does not authorise retrieval. Register it paused first:

   ```sh
   npm run sources:discover -- --configure csc-degree-directory --reason 'Reviewed official identity, robots policy, detail template and cycle handling.'
   ```

3. After the reviewed worker is deployed and an operator authorises retrieval, enable that one directory with `--enable`; leave automatic publication off for initial observation. Explicit `--automatic` enables the existing evidence policy, never unconditional publication. Use the operator controls to record the reason and independently pause either setting. CLI commands use the environment's configured database; verify the target before any write.
4. Run one explicit directory check, then selected discovered candidates. The CLI reports new/known candidates, exclusions, genuinely new/updated scholarships, unchanged records, review and failures separately. No results means no catalogue additions. Do not use `--register-details` as evidence of independent discovery.
5. Inspect exceptions and evidence before resolving them. Unsupported identity/cycle/layout is not permission to bulk accept. Pause with the same `--configure` command without `--enable`/`--automatic`. Source failure preserves last success and accepted records. Do not enable production schedules as part of onboarding without authorisation.

For reproducible live verification, create/migrate an **empty loopback database whose name contains `test`**, set `TEST_DATABASE_URL`, then run:

```sh
node --import tsx scripts/verify-discovery-expansion.ts
```

This script refuses non-loopback/non-test targets, checks three directories, processes at most five selected URLs actually discovered from them, re-fetches at most two publications, records version/event counts, and pauses all three local policies in `finally`. It does not load production environment credentials. Use `npm run db:test-migrate` with the same explicit test URL first. Never reset an existing database for this check.

## Verification

The baseline unit suite had 108 passing tests. Expanded tests cover unknown URLs, exact passages, funded versus admission levels, ambiguous cycles, canonical/path safety, directory classification/pagination, bounded JSON-LD, PDF parsing and unsupported PDFs, source media contracts, concurrency, duplicate identities, immutable versions, review, retrieval failure and downstream matching/notification idempotency. Publication tests use newly created isolated databases and all eight existing migrations; no accepted/student data was copied.

TypeScript, ESLint, all 118 unit tests, all 44 PostgreSQL integration tests and the production build pass. Integration verification used a fresh `grantpath_expansion_final_test` database on the isolated loopback cluster. Repeating the original growth test many times in an earlier test database accumulated enough identically named fixture records to push its new record beyond the first catalogue page; that run failed. No accepted database was reset; the final full run passed against a newly created empty database.

The initial browser run passed 12/14 journeys and exposed a regression introduced here: unchanged checks had been mixed into the existing publication-history API, hiding the accepted event provenance at the head of the list. The API contract is restored; unchanged checks now have their own response property and operator panel. A regression assertion covers both. Historical Python/TestSprite sources were not altered to make the checks pass.

The existing Next.js 16.4.3 build also exited with a security advisory after compilation. `next` and `eslint-config-next` were patched to 16.4.6, the non-major fix identified by npm, and the production build now exits successfully. PDF.js is pinned to 6.5.438. npm install still reports 16 existing dependency advisories (13 moderate, three high, including the Prisma/effect dependency chain); this increment does not claim a clean dependency audit or perform an unrelated major Prisma migration. A later read-only advisory recheck encountered a registry connection reset. Sandbox port restrictions required rerunning the build with approval; no compiler/security checks were disabled.

The final production-browser run passes all 14 journeys in 2.9 minutes, including all nine preserved reusable Python sources executed locally. This is local Playwright verification, not a paid TestSprite execution. The operator mobile screenshot was inspected; publication event provenance and the separate unchanged-check panel are visible. TypeScript, lint and formatting checks pass; `git diff --check` is clean. The non-empty-database refusal was also exercised and correctly exited before policy/source mutation.

No deployment or merge was performed. The temporary PostgreSQL cluster was stopped after verification; its isolated data directories remain under `/private/tmp` for optional inspection. Existing `.env` and accepted databases were left unchanged. New source definitions require explicit operator registration/activation after deployment.
