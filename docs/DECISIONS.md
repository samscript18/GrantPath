# Architecture decisions

- **2026-10-24 — Domain boundaries:** server modules own accounts, profiles, scholarships, evidence, eligibility, applications, monitoring, notifications and operator administration. UI/actions delegate business rules to modules.
- **PostgreSQL everywhere:** use local PostgreSQL for verification and Neon-compatible PostgreSQL for hosting; no production mock or in-memory persistence fallback.
- **Transactional outbox:** accepted versions, audit history and pending events commit together. Durable database workers can run standalone; Inngest invokes bounded processing, never implying that execution moves off Vercel.
- **Evidence before certainty:** missing/conflicting evidence yields unknown. Publication is reviewed; source failure retains accepted data. No inferred cycle dates or GPA conversion.
- **Hosting:** implement the explicitly requested Next.js/Vercel stack in this repository. Sites-specific Vinext/Cloudflare deployment is not used because it conflicts with the requested stack.
- **External gates:** prepare runnable configurations and concise suites; never claim remotely configured protection without authentic account evidence.
- **Rule logic:** strong three-valued AND/OR semantics. Exemptions are explicit OR alternatives, so missing or failed unused alternatives cannot invalidate a satisfied group. Requirements with missing/conflicting source evidence cannot establish failure.
- **Evaluation freshness:** immutable records keyed by user, cycle, profile version, scholarship version and engine version. Reads require exact current versions. Workers recheck both versions under transaction locks before inserting; obsolete work is skipped rather than overwriting newer state.
- **Ranking:** explicit destination/field/institution/funding preference points, separate from eligibility and availability. No award-probability percentages or GPA conversion.
- **Current qualifications:** completed qualifications are recorded separately from current study; original grading scales and experience months/hours are retained without invented conversions.
- **Source ingestion and matching:** fetches run only in standalone CLI/GitHub ingestion, using known public hosts and exact adapter paths, no redirects, robots checks, bounded response size/time, persistent per-host pacing, source leases and retry backoff. Matching/notifications use a separate paginated outbox worker. A live extraction is a candidate, never self-verifying publication.
- **Email idempotency:** stable per-delivery Resend idempotency keys. [Resend documents a 24-hour retention window](https://resend.com/docs/dashboard/emails/idempotency-keys); after an interrupted delivery has aged 23 hours, the worker records uncertain acceptance and refuses blind resend. Sink capture and provider acceptance are distinct from recipient delivery/receipt.
- **Notification defaults:** in-app topics enabled, scholarship email opted out. Current preferences and saved/current-match relevance are checked at delivery. Confirmed closing instants only; seven-/one-day windows are bounded by the actual clock and replay keys include the cycle, closing instant and window.
- **Scheduler execution:** Inngest’s signed HTTP adapter invokes bounded application work on the hosting runtime. It does not move source fetching off Vercel. The standalone GitHub application-jobs workflow is an alternative scheduler; activate one scheduler after checking free usage terms.

- **Final review safeguards:** source acceptance separately confirms existing cycle identity; new cycles remain separate opportunities. Operational deadline/availability/funding labels need checked official evidence at publication. Multi-date/time extraction returns no instant. Reminder delivery rechecks its actual seven-/one-day window, suppressing delayed stale work.
- **Profile idempotence:** compare canonical object-key order while preserving array order, because PostgreSQL JSONB can reorder keys. Unchanged stage saves do not create profile versions or recalculation events.
- **Release browser environment:** run critical journeys against the built production server as well as development. Independent browser tests use separate simulated documentation-range client IPs; server authentication throttles remain enabled.

- **Bounded reminder progress:** exclude existing durable reminder identities before applying the batch limit. Explicit UTC clock parameters keep database session time zones from changing boundary comparisons; unique outbox keys still arbitrate concurrent schedulers. Application-link changes enter the review queue; operators decide the accepted destination.
- **Observed Neon latency:** retain atomic publication with bounded 20-second interactive transactions rather than Prisma's five-second default, after an actual remote seed rollback. Batch outbox fan-out/reminder inserts to reduce network round trips. Optional Inngest steps handle one job/delivery each; the standalone worker remains separately runnable.
- **Hosted preview release:** use a dedicated Neon PR database and branch-scoped unique auth secret while Neon branch API credentials are absent. This isolates records, not compute/owner role. Vercel Hobby preview is publicly browseable, clearly labels unavailable mail, and rejects real-email signup until a verified sender exists.
- **Authentic App gate:** require observed context TestSprite V3 from verified App 2756476 (testsprite), together with github-actions correctness App 15368. Preserve automatic portal trigger and strict administrator enforcement. CLI-authored native V3 plans are visible/reviewed in the portal; only actual App executions count as PR verification.

- **No domain purchase:** user explicitly keeps the Vercel URL and EMAIL_FROM=onboarding@resend.dev. Retain this configured sender for Resend testing. The shared sender cannot provide arbitrary-recipient production authentication; public preview stays clearly labelled with isolated mail/test accounts. No domain purchase or claimed email delivery.
- **Brevo replaces Resend:** user-specified provider switch takes precedence over the original stack preference. Use the native transactional HTTPS API without another SDK. Stable UUIDv5 keys satisfy Brevo's key format. Current documented TTL is 30 minutes; stop retry at 29. Duplicate responses without message ID and provider transitions become uncertain, with provider/key audit columns; never infer receipt.
- **Reusable TestSprite assertions:** replace incomplete generated exports with explicit Python scripts whose exact local execution passed. Keep all intended filter, funding, profile and progress assertions. The next App run verifies these scripts together with the Brevo release; no manual duplicate run.

- **Google authentication:** optional server-only credential pair enables the built-in Google provider. Persist standard Prisma accounts/sessions/state, encrypt OAuth tokens, request basic online identity scopes, send new students to onboarding and returning students to the dashboard. Require a verified Google email and verified existing local email for implicit same-email linking. Different emails stay separate; roles remain server-controlled. No Google SDK dependency.
- **Appearance:** semantic CSS variables cover surfaces, brand panels, funding/eligibility/status tones and forms. A static early head script resolves browser storage/system preference before content paints; a native accessible selector persists System/Light/Dark, listens for OS/tab changes and tolerates blocked storage. Fixed forest brand panels remain readable in both palettes. No theme dependency or server cookie rendering.
- **Password guidance:** one shared Zod policy requires 10–128 characters with lowercase/uppercase/number/symbol for new passwords. The server enforces it on signup/reset/change/set; existing credentials are not subjected to composition rules during login. Confirmation is form validation and is not sent to the auth API. Independent eye buttons preserve values, permit password managers/pasting and expose accessible labels/pressed states; checklist checkboxes are read-only indicators.

- **Original account method:** the later user instruction supersedes verified same-email linking. Persist the original method in User.authMethod, derive new values from trusted auth endpoint context, disable social linking and prevent Google accounts from establishing password credentials through reset/set/change paths.
- **Verification resend:** one hashed normalized email key and an atomic conditional PostgreSQL upsert enforce a 120-second wait across requests/processes. The UI reads the remaining server duration and displays a countdown; reloading does not bypass the server lock.
- **Original academic results:** retain original scale/classification/direction and provider-specific evidence. A searchable official reference collection is guidance, not an automatic global conversion engine. Inverted scales require confirmation under engine 1.2.0.
- **Stable workspace navigation:** a shared route-group layout owns the sidebar/header; individual pages retain authorization and business-module calls. Next Form handles GET search transitions, and inline notification saves avoid refreshing unchanged server content. The content loading/error boundaries preserve navigation instead of replacing the entire workspace with a splash. React cache only deduplicates current-user lookups within a server request; it is not a shared session cache.
- **User-directed UI pause:** do not run tests, invoke paid checks or push this UI increment while the user asks to focus on design. Record unverified UI work explicitly rather than reusing earlier check results.

- **Visual redesign:** preserve the user's preferred palette and typography; improve page composition and information hierarchy rather than replacing the brand. Use repo-native decorative SVG artwork, real scholarship examples and persisted counts. Local browser screenshots are permitted visual review, distinct from the paused automated test suites. Authenticated and operator states remain explicitly unreviewed where existing local access is unavailable.

- **Profile overview:** `/profile` is the account identity overview with a dedicated navigation item; `/settings/profile` retains staged scholarship-profile editing. A saved-answer foundations bar replaces the reference image's unrelated gamification. Names and avatars use private, origin-checked account services and conditional updates. Store only bounded 256px JPEG avatars in existing User.image; normalize raster uploads in the browser and validate/re-encode with pinned Sharp on the server, retaining no uploaded metadata. No filesystem upload persistence, paid storage or fabricated profile activity.

- **Account controls follow-up:** the user's Cloudinary request supersedes database data-URL storage for new photos. Use native signed SHA-256 uploads/destroy without another SDK or unsigned preset; persist ownership before upload, publish conditionally and persist cleanup across account deletion. Retain existing Google/data URLs until the user replaces/removes them.
- **Verified in-app password changes:** use Better Auth's installed password crypto format, with an encrypted staged credential hash and purpose/session-bound six-digit email challenge. Current password plus email confirmation precede any credential change; success atomically consumes challenges and revokes all sessions. Block native set/change endpoints; keep separate email-link forgotten-password recovery. No Google-password fallback.
- **Privacy controls:** authenticated, one-time POST download of an AES-GCM-at-rest export; memory-only random token, 24-hour expiry and request cooldown. Seven-day verified/cancellable deletion window, followed by worker-driven private-data erasure and durable Cloudinary cleanup. Show actual cancellation boundary and scheduler dependency instead of promising immediate deletion. Purpose-separated encryption derives from the existing auth secret; app and worker must share a stable value.
- **Settings composition:** time-zone editing belongs in app settings; academic guidance gets its own main navigation item. Remove the static accessibility section instead of presenting a setting with no control. Sessions show recorded refresh timestamps, not invented exact activity.

- **Login profile prompt:** reuse the versioned four-step profile form inside a native accessible dialog. Persist an explicit completion timestamp after six core matching facts and final save; optional provider-specific answers may remain unknown. Completion is not eligibility. Session-scoped dismissal prevents repeated prompts on navigation while allowing another prompt after the next sign-in. Operators are not forced through student onboarding.
- **Provider images:** store institutional identity once on Provider, with an official source URL and an auditable operator update, instead of copying a logo into every saved application. All cycles and saved records inherit the provider identity. Shared Cloudinary assets use provider ownership independent of the uploading operator. Preserve existing images on fetch/upload failure; use initials where no reviewed asset exists. Reject social-network icons during visual review.
- **Compact save controls:** one shared bookmark toggle exposes accessible action names/pressed state and asynchronous feedback. Catalogue toggles persist inline; detail/saved-page refreshes update dependent application content. The user authorised committing the complete worktree; this does not authorise a GitHub push or resumed paid testing.

- **Second design pass:** preserve the exact palette/type families; improve reading hierarchy and task placement. Use container queries for scholarship facts because catalogue and saved layouts have different available widths at the same viewport. Keep factual availability, funding and evidence wording visible and separate from save/progress actions. Profile-based dashboard guidance uses the existing readiness module; its count is explicitly not an eligibility score.
- **Navigation and reading flow:** group desktop links without changing URLs, keep mobile navigation reachable, and use Next Form for the real header search. Saved-plan actions navigate to actual owned application anchors. Academic sources are grouped by real region, with search above explanatory guidance. No new database fields, service credentials or dependencies are introduced by this presentation increment.

- **25 October2026 — Global identities:** retain legacy destination display and immutable JSON versions; add indexed ISO destination arrays/scope to accepted records. Actual study institutions/countries, citizenship/residence, preferences and provider country remain separate. Participating/global/unconfirmed are scopes, never invented countries. Version1.3.0 refreshes ranking context while retaining old evaluations.
- **Approved discovery and deterministic acceptance:** explicit official directory/detail/application roles, host/path policies, bounded pagination/details, per-host pacing/robots and persistent leases. A reviewed mapping must match critical passages and structural contracts. Strong mappings protect full semantic sections and support only explicit field grammars. Incomplete useful overviews retain a mandatory confirmation rule and cannot claim a live application window. Unsupported layout/text removal, uncertain cycle/date/semantic changes and source conflicts become exceptions. Unsafe source identity is rejected. Manual and automatic acceptance share one PostgreSQL transaction/publisher/outbox, preserving reversal history and deduplicating retries.
- **Isolated release fixtures:** opt-in requires a database with a distinct test name and authenticated operator. Labelled fictional snapshots exercise the actual discovery/publication services; no network fetch targets those fictional paths. Real recipients cannot receive fixture alerts. These are verification controls, not a public reset/role-escalation mechanism. Application jobs remain separate from standalone source fetching.
- **Resumed release work:** the latest user explicitly authorises local checks, external operational configuration and coherent review pushes again. No merge, paid plan, domain purchase or promotional submission is authorised. Preserve the real required Apps and50-credit TestSprite reserve.

Neon transport: retain verified TCP by default; offer official Prisma Neon adapter with TLS WebSocket443 when TCP5432 is inaccessible. Runtime transport does not change migration DIRECT_URL or weaken certificate verification. Source/candidate/programme fingerprints and explicit directory/detail/application URLs are recorded in observation validation. Student freshness distinguishes successful programme verification from listing checks. GitHub App metadata403 is respected; a concrete PR description is prepared locally instead of attempting the same rejected write through another identity.

Discovery must do more than revisit curated URLs: the Makerere adapter now recognises previously unseen announcement IDs with an exact official provider/main-campus identity and bounded master/undergraduate academic-cycle headline grammar. It derives stable programme/level/cycle identities from that supported structure. Dates, funding and mandatory conditions stay explicitly unknown, so an automatically published incomplete cycle cannot become definitively eligible. Identity/layout/unsupported-cycle drift goes to review; no general crawler or AI acceptance was introduced. Curated mappings retain precedence, preserving their stronger accepted facts. This dynamic template has deterministic/unit and real-service PostgreSQL coverage; newly fetched live use is reported separately.
